# Kanjian 项目总纲与授权设计 v1.1

- 文档状态：开发评审修订稿
- 版本：v1.1（基于 v1.0；修订项见文末「修订记录」）
- 日期：2026-11-03
- 修订依据：`REVIEW_v1.md`（v1.0 评审问题清单）
- 项目名：**Kanjian**（工作代号，正式公开前须做名称与商标检索）
- 项目性质：开源、公益导向的视障环境理解辅助工具

> 本文是文档集入口。项目不是自动导航或自动避障系统，不替代盲杖、导盲犬、专业定向行走训练或使用者判断。

## 1. 一句话定义

把摄像头中的环境转换为**简短、可打断、带不确定性提示的语音描述**，帮助视障用户理解周围场景；系统只描述观察到的信息，不替用户作出行安全决策。

## 2. 已锁定的产品决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D-01 | 首版做“环境描述”，不做路径规划、自动避障或通行决策 | 降低安全风险，也避开“盲道识别—路径规划—反馈”等专利密集区 |
| D-02 | Android 手机 App + 可替换推理服务先行，不自研硬件 | 缩短验证周期，避免硬件认证、外观及结构专利问题 |
| D-03 | 摄像头可按 0.5/1 fps 采样，但**推理与播报采用事件触发** | 采样频率不等于理解频率，更不等于语音输出频率 |
| D-04 | 单通道串行播报、用户请求优先、队列最多保留一条待播消息 | 避免多路语音混杂和信息堆积 |
| D-05 | 端侧负责帧筛选、状态机和降级；云侧负责复杂视觉语言理解 | 控制延迟与持续云成本 |
| D-06 | 不做人脸识别、身份识别或陌生人画像 | 隐私与伦理边界 |
| D-07 | 默认不保存原始图像、不建立用户账户、不上传连续视频 | 数据最小化 |
| D-08 | 所有距离、方向和安全相关表达均受输出策略约束 | 单目摄像头不得无依据输出精确距离，不得说“可以安全通过” |
| D-09 | 首版以 Apache-2.0 为软件主许可证，并保留未来模块级分层空间 | 兼顾传播、专利条款与未来商业集成 |
| D-10 | 未通过分级验证前，不宣传“可独立出行”“可安全避障” | 防止误导性安全承诺 |

## 3. 非目标

首版明确不做：

1. “向前走”“可以过马路”“现在安全”等行动指令。
2. 以盲道为基准的路径规划、偏离纠正与自动导回。
3. 多路音频按风险动态混音或音量调度。
4. 自研眼镜、盲杖、戒指等硬件。
5. 人脸识别、熟人识别、情绪识别。
6. 全天候后台持续上传视频。
7. 医疗诊断、康复治疗或医疗器械功效声明。
8. 以模型准确率证明出行安全。

| `04_TDD_技术详细设计_v1.1.md` | 技术栈、接口、数据结构、算法与实现约束 |
| `05_TEST_测试与验收策划_v1.1.md` | 测试层级、指标、数据集、分级放行条件 |
| `06_BACKLOG_里程碑与需求追踪_v1.1.md` | 里程碑、工作包、需求—设计—测试追踪矩阵 |

本项目术语：

- **SDD**：Software Design Description，软件设计说明。
- **TDD**：Technical Design Document，技术详细设计；本文档集中不指 Test-Driven Development。
- **采样帧率**：摄像头被读取的频率。
- **推理触发率**：实际发送给 VLM 的帧数比例。
- **播报占空比**：语音正在播放的时间占总使用时间的比例。
- **描述**：对可见场景、物体、文字及其不确定性的表达，不包含行动建议。

## 5. 授权与合规设计

### 5.1 起步阶段：简单、可执行、可保留选择权

| 资产 | 授权策略 | 执行文件 |
|---|---|---|
| 项目原创软件代码 | **Apache License 2.0** | 根目录 `LICENSE` |
| 必须保留的归属信息 | Apache-2.0 要求 | `NOTICE` |
| 第三方组件与模型清单 | 文件级记录，不以仓库标签代替审查 | `THIRD_PARTY_NOTICES.md` |
| 项目文档 | **CC BY-SA 4.0** | `docs/LICENSE` |
| 评测集与标注数据 | 原则上 CC BY-SA 4.0；另附数据来源、授权和限制说明 | `DATA_CARD.md` |
| 自研微调权重 | 跟随基座许可证；默认 Apache-2.0 基座，另附模型卡和使用政策 | `MODEL_CARD.md`、`WEIGHTS_LICENSE` |
| 项目名称与标识 | 不因代码开源而授权商标使用 | `TRADEMARK.md` |
| 安全边界 | 不作为出行安全保证，不替代辅助工具 | `SAFETY.md` |
| 隐私规则 | 图像、日志、云端传输与删除机制 | `PRIVACY.md` |
| 漏洞报告 | 受理渠道、响应与披露流程 | `SECURITY.md` |

### 5.2 为什么不是 MIT

Apache-2.0 含明确的贡献者专利授权及专利诉讼终止机制；MIT 没有同等明确的专利条款。对于涉及摄像头、视觉算法和语音交互的项目，该差异具有实际意义。

### 5.3 贡献者与未来重授权

1. 首次接受外部代码前发布 `CONTRIBUTING.md` 与 CLA。
2. CLA 至少覆盖：贡献来源声明、版权许可、专利许可、项目维护与合规再授权安排；正式文本须由律师审核。
3. **DCO 只证明贡献来源，不当然赋予维护者单方面更换许可证或双授权的权利。**
4. 未签署适当 CLA 的外部贡献，不进入计划未来独立分层的核心模块。
5. 每个 PR 更新文件级第三方依赖记录；禁止把来源不明的模型、图片、语音或数据直接提交进仓库。

### 5.4 未来分层触发条件

只有出现真实硬件厂商集成或托管服务需求时，才评估拆分：

- 服务端核心：`AGPLv3` 候选；
- 硬件适配 SDK：`LGPLv3` 候选；
- 客户端与模型权重：分别审查，不能简单随代码一起换证。

分层前必须满足：模块边界清晰、全部相关贡献者权利可处理、依赖兼容矩阵复核、用户迁移方案完成。**不得仅通过修改根目录 LICENSE 文件实施换证。**

### 5.5 基座与第三方准入

- 优先选择 Qwen3-VL、CosyVoice 等明确采用 Apache-2.0 的对应发布件，但仍须核对实际下载版本的文件级许可证。
- 不因“可下载”推定“可商用”或“可再分发”。
- 禁止混入权重为 CC-BY-NC 等仅限非商业用途的组件，除非整个项目明确接受其全部传播限制。
- 模型 API 服务条款与模型权重许可证是两件事，分别审查。

## 6. 工程治理基线

首个公开版本必须包含：

```text
/LICENSE
/NOTICE
/README.md
/SAFETY.md
/PRIVACY.md
/SECURITY.md
/CONTRIBUTING.md
/CLA.md
/THIRD_PARTY_NOTICES.md
/TRADEMARK.md
/docs/LICENSE
/docs/MODEL_CARD.md
/docs/DATA_CARD.md
/docs/v1/*        ← v1.1 文档集入库位置（当前编辑副本在 `Kanjian_开发策划文档_v1/v1.1/`）
```

入库时以 `docs/v1/` 为唯一正式路径；工作区副本目录名不作为仓库路径，避免同一文档存在两个“权威版本”。

README 首屏必须显示：

1. 项目是环境描述辅助工具，不是导航或避障设备。
2. 当前验证等级与未完成验证的场景。
3. 数据是否离端、默认保存什么。
4. 如何构建、如何关闭云端、如何删除数据。
5. 软件、文档、模型、数据各自许可证入口。

## 7. 评审基线

本 v1 文档集通过评审的最低条件：

- 所有 PRD 需求均能映射到 SDD/TDD 与测试用例；
- **每条 P0 功能与每项可测非功能目标均持有唯一 ID，无编号需求不得计入 MVP 完成度**；
- 不出现“安全通过”“自动导航”等越界承诺；
- 端云接口支持替换 VLM/TTS 提供方；
- 云端关闭后 App 仍有明确、有限且可解释的降级行为；
- 成本可由采样率、触发率、图像 token、输出长度和播报占空比参数化计算；
- **存在可执行的预算/并发上限需求，且超限有明确用户可见行为**；
- 端到端超时预算与 P95 延迟目标不冲突，两者关系在 TDD 显式定义；
- 授权、隐私与安全文件与代码同步进入首个公开提交。
