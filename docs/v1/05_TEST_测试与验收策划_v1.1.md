# Kanjian 测试与验收策划 v1.1

- 版本：v1.1｜日期：2026-11-03｜状态：开发评审修订稿
- 上游：PRD v1.1、ARCH v1.1、SDD v1.1、TDD v1.1
- 修订依据：`REVIEW_v1.md`；变更明细见 00 §9「修订记录」

## 1. 测试目标与边界

测试验证三件事：功能是否按设计工作；输出是否越过安全与隐私边界；在明确的设备、网络和模型条件下，延迟、成本与稳定性是否达到工程目标。

**测试不能证明真实道路环境绝对安全。** 即使测试集上识别率很高，也不得推导出“可独立出行”或“零漏报”的结论。

## 2. 测试分层

| 层级 | 内容 | 频率 |
|---|---|---|
| L1 单元测试 | 帧差、调度、去重、策略、存储、成本计算 | 每个 PR |
| L2 契约测试 | JSON Schema、错误码、Provider 能力、两端一致性 | 每个 PR |
| L3 组件集成 | Camera→Trigger→Inference→Policy→Speech | 每日/发布前 |
| L4 故障注入 | 断网、超时、429、5xx、迟到、非法JSON、TTS失败 | 每日/发布前 |
| L5 真机性能 | 延迟、内存、功耗、温升、长稳 | 里程碑 |
| L6 准确性与对抗 | 场景、方位、幻觉、提示注入、绕过表达 | 数据集或模型变化时 |
| L7 无障碍与共创 | TalkBack、操作流程、信息负担、可理解性 | 每个候选版本 |
| L8 合规与隐私 | 抓包、清除、日志、许可证、密钥扫描 | 每个候选版本 |

#### 3.5.1 预算与限流

| ID | 用例 | 通过标准 |
|---|---|---|
| TEST-COST-001 | 请求数达日上限（默认 300 次） | 自动模式立即暂停；有一次可感知播报；手动询问仍可用且每次提示 |
| TEST-COST-002 | 估算费用达日上限（默认 ¥3.00，含未知项按保守上界） | 同上；未知 token 不被当作 0 而漏算 |
| TEST-COST-002a | **达 80% 阈值** | **仅播报一次提醒，不改变状态、不重复打断**（ADR-10） |
| TEST-COST-002b | **单会话 100 次上限** | **达上限暂停自动模式，手动可继续** |
| TEST-COST-003 | 预算周期重置 | 自动模式按用户原设置恢复，不静默重新开启 |
| TEST-COST-004 | 网关并发超限 | 快速返回 `RATE_LIMITED`，客户端不堆队列，不产生"排队等待"型长延迟 |
| TEST-COST-005 | 预算统计持久性 | 杀进程重启后当日累计不丢失（否则上限可被绕过） |
| TEST-COST-006 | **上调阈值至 10 倍硬顶** | **允许上调并读出预计日费用；超过 10 倍被拒绝；无关闭保护的入口**（ADR-10） |

| TEST-CFG-003 | 运行中修改配置（关闭云端/降低触发率） | 立即生效；未发送任务作废；在途结果不播报 |

|---|---|---|

## 4. 性能测试方法

### 4.1 必须固定的条件

设备型号与系统、App 版本、模型与 Provider 版本、图像分辨率/压缩质量、网络类型与带宽/丢包、采样 fps、触发率、播报长度、是否本地 TTS、并发与限流。

### 4.2 分段计时

```text
T_capture → T_compress → T_request_start → T_provider_first/complete
→ T_normalized → T_policy_done → T_tts_start → T_playback_end
```

至少报告 P50/P95/P99、样本数和失败率。模型完成时间与语音播放时间分开，禁止只选最短链路宣传“端到端延迟”。

**口径强制要求（R-01）**：P50/P95/P99 **只在成功样本上计算**；超时、失败、降级样本单列失败率与超时率，不得混入分位数，也不得为美化指标而剔除慢样本。每次报告必须同时给出成功样本数、总样本数、失败率、超时率；缺任一项的报告无效。

### 4.3 成本场景

1. 纯手动：按实际询问次数；
2. 1 fps、5% 云端触发；
3. 1 fps、100% 云端触发（风险对照）；
4. 自动模式但静止画面（验证接近零调用）；
5. 本地 TTS 与云端 TTS 分开核算；
6. **预算上限触发：将阈值调至最低，验证自动模式暂停、用户被告知、手动仍可用（NFR-COST-002）。**

缺失 token 账单数据时标“未知”，不得按0计。

## 5. 准确性评测设计

### 5.1 数据集

- 来源合法、用途明确、授权可追溯；不默认收集真实用户出行视频。
- 场景覆盖室内、室外静止、光照变化、遮挡、模糊、透明物体、小目标、文字与空场景。
- 样本记录采集条件和标注者分歧；不能把主观推测当唯一真值。
- 按场景划分训练/调参/测试，避免相邻近重复帧泄漏。
- 发布数据前重新审查人脸、门牌、车牌、位置等信息。

### 5.2 指标

| 指标 | 定义方向 | 注意 |
|---|---|---|
| 场景描述正确率 | 与标注事实一致 | 分开评价事实与语言流畅度 |
| 物体误报率/漏报率 | 对约定目标集统计 | 不等同现实出行风险 |
| 方位正确率 | 相对摄像头坐标 | 不宣称真实导航坐标 |
| 幻觉率 | 无依据物体/文字/属性 | 严重类型单列 |
| 不确定性表达充分率 | 低质量输入是否保留不确定 | 不鼓励所有内容都含糊 |
| 违规输出放行数 | 经端侧策略后仍可播报的越界内容 | 发布门槛为0（对抗集） |
| 重复播报率 | 冷却期内无新事实播报 | 结合用户主观烦扰评价 |
| 有效信息密度 | 有用事实数/播报字数或时长 | 防止长而空 |

不设置“识别率达标即允许独立出行”的转换规则。

## 6. 共创与伦理

1. 先由研发团队在静态或有人陪同的受控环境测试，再邀请视障参与者。
2. 参与者知情同意、可随时退出，不以其是否完成危险动作评价产品。
3. 不安排真实车流穿行、无保护道路穿越或依赖系统进行避障的测试。
4. 测试期间保留既有辅助工具与陪同人员，明确系统随时可能错误。
5. 记录信息负担、信任变化和误用倾向，而不仅是任务完成时间。
6. 反馈原话须匿名化，引用前再次取得许可。

## 7. 分级放行

| Gate | 环境 | 必备条件 | 允许的使用方式 |
|---|---|---|---|
| G0 | 模拟/Fake Provider | 单元、契约、策略通过 | 开发演示 |
| G1 | 实验室受控图像 | 集成、故障、隐私通过 | 研发内部 |
| G2 | 静态真实环境 | 真机性能、准确性基线、TalkBack通过、**默认状态与首次说明通过（TEST-ONB/CFG）** | 受邀体验，明确非安全工具 |
| G3 | 有人陪同的受控动态场景 | 共创问题闭环、无阻断级缺陷、**预算上限演练通过** | 有限试点 |
| G4 | 公开测试 | 文档、支持、退出与降级机制齐全、**发行包端点扫描通过（TEST-DEF-001）** | 公开Beta，仍不作独立出行承诺 |

任何安全策略、模型、图像分辨率或调度逻辑的实质变化，都需回归相关 Gate；重大变化不得直接沿用旧报告。

## 8. 发布阻断项

- 云端关闭后仍上传图像；
- 行动指令或身份识别绕过策略并可播报；
- 迟到结果无法隔离、队列持续增长；
- 停止后仍播放；
- 默认保存图像或日志泄漏图像；
- 核心 TalkBack 流程阻断；
- 许可证/数据来源不明；
- 使用“安全、可靠避障、独立出行”等未经验证的宣传；
- 测试报告缺少设备、模型、网络或样本量信息；
- **公开发行包含预置云端端点或维护者密钥（ADR-07）；**
- **自动观察在用户未显式开启时即产生云端请求（FR-CFG-002）；**
- **未完成首次说明即进入采集或推理（FR-ONB-001）；**
- **预算超限后静默继续消耗云端额度（NFR-COST-002）；**
- **性能报告混用成功样本与超时样本计算 P95，或缺失失败率/超时率（R-01）。**
