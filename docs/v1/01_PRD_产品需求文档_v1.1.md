## 1. 背景与问题

视障用户获取环境信息时，常见工具存在三类缺口：传统导航在目的地附近和临时障碍方面信息不足；通用图像描述应用往往输出过长、过于文学化；连续播报又会占用用户感知环境声音所需的听觉通道。

Kanjian 要解决的不是“替用户看路并指挥行走”，而是：**在用户需要时，用尽可能短的话说明摄像头里看到了什么，并明确哪些内容不确定。**

## 2. 产品原则

1. **先少后准**：少播报、短句、可打断，优先于“说得丰富”。
2. **事实与推断分离**：看见的内容、模型推测、无法确认的信息分别表达。
3. **不做安全决策**：不输出通行、方向调整或路线选择建议。
4. **用户始终可控制**：开始、暂停、询问、打断、删除、关闭云端均可操作。
5. **隐私默认开启保护**：不上传连续视频，不默认存图，不做人脸识别。
6. **失败要可感知**：超时、离线、低置信度必须明确告知，不能静默编造。

## 3. 用户与使用前提

### 3.1 目标用户

- 成年视障或低视力用户；
- 为视障用户提供支持的亲友、无障碍研究者与开发者；
- 首版不面向无人监护的儿童独立使用。

### 3.2 使用前提

- 用户理解本产品只是补充信息来源；
- 户外使用时仍需使用其既有辅助工具并留意环境声音；
- 建议使用开放式音频播放方式，不以音量遮盖交通等环境声音；
- 首次启动必须完成安全与隐私说明，不可仅以小字链接呈现。

### 3.3 非目标用户承诺

不向用户承诺：独立出行保障、障碍物零漏报、交通灯通行判断、精确测距、医疗或康复效果。

## 4. 核心场景

| 场景 | 用户问题 | 系统输出示例 | 明确禁止 |
|---|---|---|---|
| S1 环境理解 | “我周围大概有什么？” | “像是一条走廊，正前方有椅子，左侧有门。” | “向左绕过去” |
| S2 主动询问 | “前面是什么？” | “看起来是垃圾桶，画面有些模糊。” | 无依据地说“两米外” |
| S3 文字阅读 | “帮我读这个牌子。” | 朗读识别出的文字；无法辨认处明确跳过 | 补写看不清的文字 |
| S4 场景变化 | 自动观察期间出现明显变化 | “画面中新增一辆停在右侧的自行车。” | 每隔一秒重复完整描述 |
| S5 找物辅助 | “帮我看看桌上有没有水杯。” | “画面中央偏右有一个像水杯的物体。” | 宣称一定找到全部目标 |
| S6 服务降级 | 无网、超时或模型不可用 | “当前无法完成云端识别，可重试或使用文字阅读。” | 离线时假装已完成理解 |

## 5. MVP 范围

### 5.1 必须有（P0）

每一项均持有唯一需求 ID；无 ID 项不得计入 MVP 完成度。

| # | P0 能力 | 需求 ID |
|---:|---|---|
| 1 | Android 摄像头预览、权限管理与拍照式单帧理解 | FR-CAM-001/002 |
| 2 | 自动观察模式：0.5/1 fps 可配置采样，端侧事件触发，不默认逐帧上云；**MVP 默认关闭，须用户显式开启** | FR-CAM-002、FR-TRG-001、FR-CFG-002 |
| 3 | 主动询问模式：语音或无障碍大按钮触发 | FR-TRG-002、FR-ACC-001 |
| 4 | 文字阅读模式：OCR 结果朗读与失败提示 | FR-OCR-001 |
| 5 | 结构化视觉理解：场景、可见物体、相对方位、文字、不确定性 | FR-VLM-001/002/003 |
| 6 | 输出安全策略过滤与敏感表达阻断 | FR-SAF-001~004 |
| 7 | 单通道语音队列、去重、冷却、打断和停止 | FR-TTS-001~005 |
| 8 | **VLM/TTS 提供方可替换；至少一个可用参考实现** | **FR-DEF-001** |
| 9 | 离线、弱网、超时、限流、权限拒绝等降级路径 | FR-NET-001/002 |
| 10 | 本地描述历史（不含原图）及一键删除 | FR-HIS-001/002 |
| 11 | TalkBack 可操作的完整主流程 | FR-ACC-001/002 |
| 12 | **首次使用安全说明、云端传输说明与隐私控制** | **FR-ONB-001/002** |
| 13 | 本地埋点与成本可观测（原 §10，未编号，本版补入） | **FR-MET-001/002、FR-COST-001** |

> 变更说明（R-06）：v1.0 仅在第 2 项写"自动观察"，未定义默认状态；06 §6 曾建议默认关闭。本版将其提升为可验收需求（FR-CFG-002），默认值定为**关闭**，由用户在首次说明后主动开启。

### 5.2 可以有（P1）

- 自定义播报长度与自动模式开关；
- 外接摄像头/眼镜的通用帧源适配接口；
- 用户自备服务端或模型端点；
- 本地 VLM 实验插件；
- 匿名、无图像的本地性能统计导出；
- 振动仅用于服务状态和用户操作反馈，不编码方向或风险等级。

### 5.3 暂不做（P2）

- iOS 正式版、账号体系、云相册、社交功能；
- 人脸/身份识别、情绪判断；
- 精确测距、三维重建、路径规划、盲道导回；
- 红绿灯通行建议、车辆意图预测；
- 硬件产品认证和量产支持。

## 6. 功能需求

| ID | 需求 | 验收要点 |
|---|---|---|
| FR-CAM-001 | 支持后置摄像头预览与帧采集 | 权限拒绝、相机被占用均有可理解提示 |
| FR-CAM-002 | 自动采样可配置为 0.5 或 1 fps | 采样频率与推理次数分别可观测，不得混淆 |
| FR-TRG-001 | 端侧根据帧差、运动和冷却策略筛选候选帧 | 静止场景不得持续产生相同云端请求 |
| FR-TRG-002 | 用户主动询问可立即触发一次新帧推理 | 不等待下一个自动采样周期 |
| FR-TRG-003 | 推理请求不得排队堆积 | 新请求按策略替换过期请求，队列有硬上限 |
| FR-VLM-001 | 输出结构化场景理解结果 | 通过 JSON Schema 校验，异常结果不直接播报 |
| FR-VLM-002 | 支持场景、物体、相对方位、文字和不确定性字段 | 缺字段有默认值，无法判断时输出 unknown |
| FR-VLM-003 | 数量描述仅限模型明确可见目标 | 不使用“全部”“没有障碍”等穷尽性表述 |
| FR-VLM-004 | 无深度依据时禁止输出精确距离 | 输出策略层复核并删除或改写 |
| **FR-VLM-005** | **`speech_candidate` 与 `text_regions` 原文不得绕过端侧策略** | **两字段均经 OutputPolicyEngine 复核；OCR 原文与 App 描述分通道** |
| FR-SAF-001 | 禁止生成行动指令与通行安全结论 | “可以走/安全通过/向右绕”等不得播报 |
| FR-SAF-002 | 禁止人脸身份识别及敏感属性推断 | 请求与响应双侧检查 |
| FR-SAF-003 | 低置信度或模糊图像须显式表达不确定 | 使用“可能是/看不清”而非确定语气 |
| FR-SAF-004 | 不得把模型未检出等同于环境安全 | 不出现“前方没有障碍物”等安全暗示 |
| FR-OCR-001 | 支持用户框定或重新拍摄文字区域 | 识别失败可重试，不自动补全缺字 |
| FR-TTS-001 | 同一时刻只播放一条描述 | 不出现多路语音叠加 |
| FR-TTS-002 | 用户可随时停止当前播报 | 停止后不得继续播放已排队旧消息 |
| FR-TTS-003 | 用户请求优先于自动场景消息 | 自动消息不得打断主动阅读/询问 |
| FR-TTS-004 | 相似描述在冷却期内去重 | 重复率可测量，冷却时间可配置 |
| FR-TTS-005 | 待播队列最多一条 | 新候选按策略替换，过期消息丢弃 |
| FR-HIS-001 | 默认仅保存最近文字描述与必要元数据 | 不默认保存图像、音频或精确位置 |
| FR-HIS-002 | 支持查看、单条删除和全部清除 | 清除后不可从 UI 恢复 |
| FR-NET-001 | 云端不可用时进入明确降级状态 | 状态可见、可语音读出、可重试 |
| FR-NET-002 | 用户可彻底关闭云端推理 | 关闭后不得发出图像请求 |
| FR-ACC-001 | 主流程兼容 TalkBack | 无仅依赖颜色、精细手势或视觉位置的必要操作 |
| FR-ACC-002 | 所有关键操作均有文字、无障碍标签与语音反馈 | TalkBack 遍历顺序合理 |
| **FR-ACC-003** | **App 自播报与 TalkBack 的音频焦点有确定默认策略** | **首版默认"不主动请求独占音频焦点"，仅短暂提示；争抢行为纳入共创测试** |
| FR-CFG-001 | 可配置播报长度、自动模式与采样频率 | 配置本地持久化，不上传 |
| **FR-CFG-002** | **自动观察模式默认关闭，须用户显式开启** | **首次启动后为关闭；开启前有一次性说明；状态可语音读出** |
| **FR-CFG-003** | **配置项变更立即生效并使在途任务失效** | 关闭云端/降低触发率后，未发送任务作废；在途结果不播报 |
| **FR-ONB-001** | **首次启动展示安全与隐私说明，不可仅以小字链接呈现** | 必须主动阅读/确认后方可进入主流程；拒绝则退出 |
| **FR-ONB-002** | **首次说明须覆盖：非导航定位、数据是否离端、默认保存什么、如何关闭云端与删除数据** | 四项均可被 TalkBack 逐条读出；版本可追踪 |
| **FR-DEF-001** | **VLM/TTS 提供方通过接口可替换，核心策略不随之改变** | 替换 Provider 不需修改 Trigger/Policy/Speech；至少一个参考实现通过同一契约测试 |
| **FR-MET-001** | **本地记录结构化运行事件（采样/触发/丢弃/超时/过滤/去重/打断/错误）** | 环形缓冲有上限；默认不上传；导出需用户主动确认 |
| **FR-MET-002** | **记录每次请求的阶段耗时与 Schema 校验结果** | 分段计时字段齐全；不含图像、原始语音、完整提示词 |
| **FR-COST-001** | **每次请求记录估算 token/费用与"未知"标志** | 缺失 token 标 unknown，不按 0 计；可导出汇总 |

## 7. 非功能需求

以下为**工程目标**，须在规定测试环境下验收，不作为对真实场景的服务承诺。

| ID | 指标 | MVP 目标 |
|---|---|---|
| NFR-PERF-001 | 主动询问到文字结果，参考网络与服务条件下 | P50 ≤ 2.0s，P95 ≤ 4.0s（**成功样本**口径，见下） |
| NFR-PERF-002 | 主动询问到语音开始播放 | P50 ≤ 2.5s，P95 ≤ 5.0s（**成功样本**口径） |

| NFR-REL-001 | 主流程崩溃-free sessions | ≥ 99.5% |
| NFR-REL-002 | 云端异常可恢复性 | 不崩溃、不死等；错误可读且可重试 |
| NFR-PWR-001 | 功耗与温升 | 建立 30 分钟基线并公开机型、设置与结果；首版不设跨机型统一承诺 |
| NFR-PRV-001 | 默认图像持久化 | 0 张 |
| NFR-PRV-002 | 默认人脸身份处理 | 0 项 |
| NFR-ACC-001 | TalkBack 主流程任务完成 | 核心任务均可完成，无阻断点 |
| NFR-COST-001 | 云成本可观测 | 每次请求记录估算 token/费用，可导出汇总 |
| **NFR-COST-002** | **云端调用预算上限** | **默认 300 次/日、¥3.00/日、100 次/会话；达 80% 播报提醒，达 100% 暂停自动模式并语音告知；手动询问可继续但计入提示；用户可上调至默认值 10 倍，不可关闭（ADR-10）** |
| **NFR-COST-003** | **网关并发与限流硬上限** | **超限快速返回 `RATE_LIMITED`，不在网关堆队列；不产生"排队等待"型延迟** |

### 7.1 延迟口径与超时预算（R-01）

v1.0 存在一处冲突：NFR-PERF-001 的 P95 目标为 4.0s，而 TDD §12 的请求总超时也恰为 4s，导致任何超时样本都必然违约、且无工程余量。本版明确如下口径：

```text
T_budget（请求总超时） = P95目标 + 缓冲
端到端超时 = 4.0s（NFR-PERF-001 P95） + 2.0s（缓冲） = 6.0s
连接超时 = 1.0s（TDD §12 不变）
```

1. **P95 指标只在成功样本上统计**（HTTP 200 且 Schema 校验通过）。
2. **超时、失败、降级样本单独统计失败率**，不计入 P95，也不得用"排除慢样本"方式美化 P95。
3. 测试报告必须同时给出：成功样本 P50/P95/P99、样本数、失败率、超时率。
4. 缓冲值不得用于掩盖慢模型：若成功样本 P95 已接近 4.0s，正确做法是降采样、换 Provider 或减少自动触发，**不得调长超时"达标"**（与 TDD §12、06 风险登记一致）。

参考网络、设备、模型版本、图像分辨率与并发条件必须写入测试报告；缺少这些条件的延迟数字不得用于宣传。

## 8. 输出语言规范

### 8.1 推荐表达

- “正前方有一把椅子，左侧还有一张桌子。”
- “画面较暗，右侧可能是自行车。”
- “识别到门牌上的文字：……”
- “看不清，无法确认。”

### 8.2 禁止表达

- “可以走了”“向右绕”“现在安全”。
- “前方没有障碍物”“路上没有车”。
- 无传感器依据的“前方 2.3 米”。
- “这是你的家人”“此人正在生气”。
- 未识别出文字时的合理猜测或补写。

## 9. 成本需求

成本模型必须参数化，不允许只给“每小时多少钱”的固定宣传值：

```text
令  云端推理次数 = 3600 × 采样fps × 云端触发率        （单位：次/小时）
则  每小时视觉成本 = 云端推理次数 × 单帧输入token × 输入单价
                   + 云端推理次数 × 单次输出token × 输出单价
    每小时语音成本 = 计费字符数 × TTS单价（仅云端TTS时计入）
```

> R-09：v1.0 公式首项写作 `3600 × fps × 触发率 × 单帧输入token × 输入单价`，次项又写 `云端推理次数 × …`，两处对"推理次数"的定义未显式等同，易在实现时被理解为两个独立计数。本版先定义 `云端推理次数`，两处引用同一变量，避免重复计数或漏计。

MVP 默认端侧 TTS，自动模式必须展示云端触发率（FR-MET-002 / FR-COST-001）。测试至少覆盖：纯手动、1 fps/5% 触发、1 fps/100% 触发三组，后者仅用于证明成本风险，不作为推荐配置。预算上限行为见 NFR-COST-002。

## 10. 埋点与评测需求

仅本地记录（FR-MET-001/002、FR-COST-001）：帧时间戳、是否触发、取消原因、各阶段耗时、响应 schema 校验结果、安全过滤命中、播报打断与去重、网络错误类型、估算成本与"未知"标志。默认不记录图像、原始语音、精确位置或完整云端提示词。

准确性评测另建经授权的数据集，记录：描述正确性、物体误报/漏报、方位正确性、幻觉、违规行动建议、重复播报率。漏报指标仅用于研究，不转化为出行安全声明。

## 11. MVP 完成定义

同时满足：

1. P0 需求通过对应测试（**P0 清单见 §5.1，每项均须有需求 ID 与测试落点**）；
2. 违规行动指令在对抗测试集上的**播报放行数为 0**；
3. 云端关闭后无任何图像外发；
4. 无网、超时、低置信度均有明确反馈；
5. 预算上限行为（NFR-COST-002）经测试验证：达阈值后自动模式确实暂停且用户被告知；
6. 视障共创测试完成受控场景任务，且无未处理的阻断级无障碍问题；
7. 文档、许可证、第三方清单、隐私与安全说明齐全；
8. 发布页不含有“可独立出行/安全避障”等承诺。
